# BNC SKL Downloader and RINEX 3.05 Signal Mapper

Python tool to download, standardize, and update IBGE RBMC station skeleton (`.skl`) files for use with BNC (BKG Ntrip Client).

## Overview

This project automates the retrieval and standardization of station-specific `.skl` files from the Brazilian Network for Continuous GNSS Monitoring (RBMC). It expands the observation signal definitions using a predefined catalog based on the RINEX 3.05 specification.

The script was developed after encountering a potential compatibility issue in which RINEX files generated by BNC from RBMC streams contained headers but no observation records. Updating the local skeleton files was followed by successful observation data collection in the tests performed. However, the exact cause of the original issue has not been conclusively established.

## Features

* Reads RBMC-IP station mountpoints from a local NTRIP Source Table.
* Downloads station-specific `.skl` files from the IBGE repository.
* Standardizes RINEX headers and observation type definitions.
* Adds predefined signal codes for seven GNSS constellations:

  * GPS
  * GLONASS
  * Galileo
  * BeiDou
  * QZSS
  * SBAS
  * NavIC/IRNSS
* Preserves existing observation codes while adding missing entries from the signal catalog.
* Generates a consolidated signal mapping report.
* Handles missing files, HTTP errors, and processing exceptions.

## Data Sources

* **RBMC NTRIP Source Table:** http://gps-ntrip.ibge.gov.br:2101/
* **IBGE RBMC SKL repository:** http://gps-ntrip.ibge.gov.br/skl/
* **BNC source code, revision 10979:** https://software.rtcm-ntrip.org/browser/ntrip/trunk/BNC/src/rinex/rnxobsfile.cpp?rev=10979

## Requirements

* Python 3
* Internet access to the IBGE RBMC SKL repository
* A locally saved RBMC NTRIP Source Table
* BNC installed and configured to use the generated local skeleton files

The script uses only Python standard-library modules; no third-party packages are required.

## Configuration

Edit the configuration variables at the beginning of the script:

| Variable           | Description                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------- |
| `SOURCE_TABLE`     | Path to the local NTRIP Source Table file.                                                  |
| `SKL_FOLDER`       | Directory for downloaded and processed `.skl` files.                                        |
| `SKL_BASE_URL`     | Base URL of the IBGE RBMC SKL repository.                                                   |
| `NAO_SOBRESCREVER` | Controls whether existing local files are reused instead of downloading remote files again. |

**Important:** Set `NAO_SOBRESCREVER = True` to reprocess existing local files without downloading them again. Set it to `False` to download and process the remote files.

Update the paths to match your operating system and local BNC installation.

## Usage

1. Download the RBMC NTRIP Source Table and save it locally.

2. Set the input and output paths in the script.

3. Run the script from a terminal:

   ```bash
   python bnc_skl_downloader.py
   ```

4. Check the terminal output for download and processing results.

5. Configure BNC to use the generated local `.skl` files.

6. Verify that the resulting RINEX files contain observation records and valid headers.

## Output

The script generates:

* **Station `.skl` files:** Standardized local skeleton files for the stations successfully processed.
* **`mapeamento_sinais.txt`:** A consolidated report of the observation codes defined for each station and GNSS constellation.
* **Execution summary:** Counts of downloaded files, reprocessed local files, missing station files, and errors.

## Technical Notes

### RINEX 3.05 Signal Definitions

The script uses a predefined catalog of observation codes associated with seven GNSS constellations. Existing codes found in each skeleton file are retained, and missing catalog entries are added.

The catalog defines potential observation types; it does not indicate which signals are actually available from a given station or present in a received RTCM stream. Actual observations depend on receiver capabilities, satellite availability, signal tracking, and the data provided by the caster.

### Potential BNC Compatibility Issue

The project originated from an investigation into a possible incompatibility between RBMC skeleton files and BNC's interpretation of their contents. The source code history provides a reference for investigating changes in RINEX observation file handling:

https://software.rtcm-ntrip.org/browser/ntrip/trunk/BNC/src/rinex/rnxobsfile.cpp?rev=10979

The relationship between these changes and the observed absence of observation records remains a hypothesis rather than a confirmed root cause.

### Validation

Before operational use, validate the generated headers against the applicable RINEX specification and the BNC version being used. Confirm that the declared observation types are appropriate for the receiver and data stream.

## Limitations

* Only stations identified as `RBMC-IP` in the local Source Table are processed.
* Some station `.skl` files may not be available from the repository.
* Adding signal codes to a skeleton file does not create or recover missing GNSS observations.
* The script's standardized header and signal catalog should be validated before use in scientific processing.
